Banc de rejeu du fil (chantier « Le coach en un fil », lot 1, 25/11/2026)
OUTIL DE CHANTIER : il n'est PAS dans la CI et ne se lance pas dans `npm test`. Il vit dans v2-atelier/ (la garde de publication
n'admet que l'app dans v2/). Aucune dépendance : node seul. Un processus à la fois (7 Go de mémoire) ; un tour dure 2 à 3 minutes.

Principe. Des histoires de séances sont rejouées contre DEUX versions de v2/js/ : A (la base : v2/js/ du dépôt, ou --base) et B (--contre).
Chaque variante joue SA trajectoire (la personne suit la consigne de la variante, tirage fixe par histoire et par séance). À chaque séance
on compare une signature : état, ligne, haut, zone, phrase d'en-tête, réserve affichée, clés du fondement, TEXTE des erreurs de
verifierPlan, paris ratés. Pour les cas ajoutés, la signature porte aussi la partie du plan que le cas exerce.
Code de retour : 0 si aucun écart, 1 sinon.

Commandes (depuis la racine du dépôt) :
  node v2-atelier/banc/rejeu-fil/banc.js --contre <dossier js>        B contre la base ; « main contre main » : --contre v2/js
  npm run rejeu-fil -- --contre <dossier js>                           la même chose
  node v2-atelier/banc/rejeu-fil/banc.js --muter [--filtre <regex>]    mutations.json, une à la fois, sur une copie de la base
  options : --base <dossier js> · --n 200 · --graine 20261125 · --erreurs (séances en erreur de verifierPlan, par invariant)
            · --couverture (les états joués) · --fixture <fichier.json>
Préparer une version à comparer : git archive <commit> v2/js | tar -x -C <dossier vide>, puis --contre <dossier vide>/v2/js.

Les histoires. 200 tirées + 120 dirigées (scripts : légère faite à P, zéro au-dessus de P, séance ratée entre deux zéros, retour,
saut de plusieurs crans, reprise longue faite au-dessus, légère prise d'elle-même après une pause), puis les CAS AJOUTÉS (tirage à part,
à la suite : les histoires d'origine jouent exactement ce qu'elles jouaient) :
  corps       tractions au poids du corps (charge 0, reps seules)           aide        tractions assistées (charge négative)
  elastique   une salle d'élastiques (crans 10 à 30)                        lest        poids du corps, reps hautes, `lestReponse` null / oui / non
  decharge    une séance sur quatre dans une semaine allégée (`allegee`)    veille      une activité dure la veille, `veilleChoix` null / leger / garder
  test        une séance sur trois en semaine de test (barre testée)
Lots 3 et 4 (26/11/2026) : scripts neutre_* (« Sans coach », « J'ai mal » dans un jour sans), decharge_* (décharge dans un jour sans), le compte du bilan (Bilan.compterParis, en dernier de la signature), débutants de
50 à 59 ans au squat (saut50). Les filtres `decharge` seuls (légère, séances lues, jeton, compteur) sont des mutants ÉQUIVALENTS : une décharge est toujours aussi `neutre` (moteur.js, marquerSousConsigne) ; de même le filtre `neutre`
des séances lues et du jeton, redondant avec `palier` nul. Ils ne sont pas dans mutations.json.
Fiche de spécialité, PR 0 (26/11/2026) : le banc VOIT LE BUT (but.js, à la suite, tirage à part). Cas `but` : 192 histoires (6 buts : force, muscle,
les_deux, forme, calisthenie, null × squat à la barre et curl aux haltères × 4 scripts de raté sousBas / sousUn / aBas / zero × 4 zones), la séance rejouée avant
toute série puis après chaque série validée ; signature : x.rate, la proposition de chauffes, la réserve affichée, la garde, les cartes, les erreurs d'invariant.
Table `programmes` : Generateur.generer sur 6 buts × 2 à 6 jours × débutant × matériel × plus65 × entretien × ménager (2 880 lignes) + carteCycles (192 lignes).
Table `blocs` : 8 buts (dont '' et 'inconnu') × Lourd, Mix, Hyp × phases (48 lignes : zonesDeBloc, zoneDuPremierBloc, grosseSerieParDefaut, blocSuivant,
carteFinDeBloc, carteSchema). Une ligne de table qui diffère est un écart (code 1) ; en --muter, une mutation est tuée à 5 histoires OU 1 ligne de table.
Fixture : champ facultatif `objectif` par histoire (absent : la règle d'avant, protegee ? forme : muscle ; null ou '' : sans réponse) et `sousConsigne` (true)
par séance. Les tables ne se jouent pas en --fixture.

Restent aveugles (non faits, lot 1 : chacun dépasse les 300 lignes) : les chauffes (`propositionDeChauffes`) et les supersets (`tours`).
Les cas sont joués sur une barre seule : le mélange de plusieurs exercices dans une séance n'est pas rejoué.

Mutations (mutations.json, 32 + 1 témoin) : { nom, fichier (relatif à v2/js/), ancien (exactement une fois), nouveau, temoin? }.
Tuée si au moins 5 histoires diffèrent ; le témoin (un commentaire change) doit survivre. Une mutation dont le texte n'est plus trouvé
exactement une fois est « non appliquée » (code de retour 1) : à réécrire quand le code change. c1 à c5 sont celles des cas ajoutés
(décharge, veille × 2, lestReponse, semaine de test).

Rejeu sur de vraies données (Claude.ai, hors dépôt) : --fixture <fichier.json> remplace les histoires tirées par de vraies séances.
Aucune personne simulée : à chaque séance la consigne et le plan sont calculés sur les séances d'avant. Format :
  { "histoires": [ { "id": "squat", "slug": "squat_barre", "equipement": "barre", "mesure": "charge_reps", "pas": 2.5,
                     "famille": "squat_barre", "zone": null, "reglage": "franc", "age": null, "debutant": false, "protegee": false, "nseries": 3,
                     "seances": [ { "debut": "2026-03-02T17:00:00Z",
                                    "series": [ { "charge_kg": 100, "reps": 5, "rpe": 8, "type_serie": "travail", "validee_a": "2026-03-02T17:30:00Z" } ] } ] } ] }
Champs facultatifs : nom, kg, salle ({ materiel: "elastique", charges: [...], aide }), rang, ressenti. Aucune donnée personnelle dans le dépôt :
la fixture reste à côté, jamais commitée.

Équipements (26/11/2026) : `EXOS` déclarait `equipement: 'halteres'` (pluriel) ; le catalogue réel dit `haltere` ou `haltere_seul`. Sans repli de matériel,
483 séances sur 7 341 sortaient en `test_propose` sans charge : un artefact du banc, corrigé (`haltere`). Le banc REFUSE désormais (erreur à la construction de EXOS et
à la lecture d'une fixture) tout équipement absent de la liste fermée EQUIPEMENTS. La comparaison base contre contre n'en change pas (les deux côtés lisent le même banc).

Le compteur de stagnation (27/11/2026, correctif du banc) : AVANT, le banc ne le voyait pas. Il valait 0 sur toutes les séances (9 077) : `seancesSousConsigne` n'était
pas passé (le `sousConsigne: true` de la fixture n'arrivait pas jusqu'au compteur) et la signature ne portait ni le compteur, ni sa phrase d'en-tête, ni la marche de l'escalier.
Les anciens « 0 écart » ne couvraient donc PAS le compteur ; toute mutation du compteur survivait. Désormais : toutes les séances d'avant comptent comme sous consigne,
et la signature porte R.compteur.compteur, la phrase du compteur (x.entete.compteur) et la marche (x.escalier.marche). En fin de comparaison une ligne « B3 compteur : {…} »
résume les écarts (compteur, remise à zéro, phrase, marche). Trois mutations le prouvent : mu-cpt1 (seuil 4 → 3), mu-cpt2 (le progrès ne remet plus à zéro), mu-cpt3 (un cran vaut 2).
